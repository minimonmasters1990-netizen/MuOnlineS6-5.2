# 修复数字加中文角色名无法存储技能的问题

## 问题分析

通过分析代码，我发现问题出在 `AllDataOfflineSave` 函数和 `LoadOfflineConfigINI` 函数中。当角色名包含数字和中文时，使用角色名直接作为文件名的一部分会导致文件操作失败，从而无法保存或加载技能配置。

具体问题点：
1. 在 `AllDataOfflineSave` 函数中（NewUIMuHelper.cpp:1603）：
   ```cpp
   sprintf(extraPath, ".\\Data\\ACuoi\\Config\\Setting\\%s.ini", currentName);
   ```

2. 在 `LoadOfflineConfigINI` 函数中（MuHelperData.cpp:102）：
   ```cpp
   sprintf(extraPath, ".\\Data\\ACuoi\\Config\\Setting\\%s.ini", Hero->ID);
   ```

当角色名包含中文和数字时，直接使用 `sprintf` 生成的文件名可能在文件系统中不被允许，导致文件操作失败。

## 解决方案

1. **创建安全文件名转换函数**：
   - 创建一个 `GetSafeFileName` 函数，检测角色名是否包含中文和数字
   - 如果是纯中文角色名，保持原有处理方式
   - 如果是中文加数字角色名，转换为安全的文件名格式

2. **修改保存和加载逻辑**：
   - 在 `AllDataOfflineSave` 函数中使用新的文件名处理逻辑
   - 在 `LoadOfflineConfigINI` 函数中使用新的文件名处理逻辑

3. **确保向后兼容性**：
   - 保留对纯中文角色名的原有处理方式
   - 为中文加数字角色名添加新的处理方式

## 具体修改步骤

1. 在 `ZzzToolKit.cpp` 中添加 `GetSafeFileName` 函数，实现以下逻辑：
   - 检测角色名是否包含中文和数字
   - 对于纯中文角色名，返回原角色名
   - 对于中文加数字角色名，返回转换后的安全文件名

2. 修改 `AllDataOfflineSave` 函数：
   - 使用 `GetSafeFileName` 函数获取安全的文件名
   - 保持对原有纯中文角色名的支持

3. 修改 `LoadOfflineConfigINI` 函数：
   - 使用 `GetSafeFileName` 函数获取安全的文件名
   - 保持对原有纯中文角色名的支持

4. 测试修复效果，确保：
   - 纯中文角色名仍然可以正常存储和加载技能
   - 中文加数字角色名现在可以正常存储和加载技能
